## Agreed purpose and constraints

The user wants a substantial year-long engineering project balancing trained ML research and a usable investigation application. This milestone advances the URL module by obtaining authentic legitimate URL formats, training only when declared support gates pass, and measuring performance on protected domains. Dataset size or a headline accuracy number is not success by itself.

Carry forward Ryzen 7 7435HS, 16 GiB RAM, CPU-first modelling, four native training threads, an 8 GiB process-tree fitting ceiling, CPython 3.11 on Windows, and the existing dependency locks. Inputs remain HTTP(S) strings of at most 2,048 characters. There are no requests to submitted destinations, HTML/pickle dataset loads, paid APIs or background browsing.

The user approved the researched Mendeley direction and retained inline implementation with one independent final review. The new source and split rules below are design decisions for review, not changes to v2. ## Why this experiment

V2's frozen development cohort has 6 legitimate query URLs against a minimum of 30. Its complete pre-cap eligible pool has only 7. Increasing that cap cannot resolve the gap while protecting final data.

The checksum-verified candidate contains 191 legitimate query URLs; 92 across 87 domain groups survive a preliminary screen against all v2 primary-reserved domains. Joint conflicts and final reservations may remove more. Those counts justify a new study, not a passing training gate or an expected detector score.

Use the measured Mendeley source alongside eligible PhreshPhish training observations. Preserve v2 and its protected domain anchors. Reserve a new Mendeley cohort before fitting, retain eligible Mendeley development components before filling the development cap with Phresh-only components, and evaluate the two final cohorts separately. Phish360 is a later candidate; access to ISCX remains pending. Neither is silently substituted into this experiment.

## Cohorts, ownership and the development cap

Use the following fixed priority: original v2 primary reservation -> new Mendeley supplemental reservation -> pooled development. Never split a connected component between these destinations.

1. **Primary final track:** components touching original protected anchors stay reserved. Score only surviving canonical cases originally owned by PhreshPhish test in the frozen v2 primary track, with surviving Phresh test observations as owners. The v3 primary row set can shrink through joint conflicts; it cannot gain new training or Mendeley-only rows. Record the retained subset and all removed original primary cases. Never return a reserved component to development because it has no remaining evaluable rows.
2. **Supplemental final track:** among the remaining components containing accepted Mendeley observations, assign a fixed half by a label-independent hash rule. Compute SHA-256 of the ASCII string `url-v3-mendeley-final|42|` followed by the component ID; interpret its first eight bytes as an unsigned big-endian integer and reserve the component when the value is below `2**63`. Component IDs are the existing digest of sorted canonical case IDs. Own and score only Mendeley observations in these components. Phresh training observations in the same components are pruned, not added to this track.
3. **Development:** remaining eligible components own Phresh published-training and Mendeley development observations. Deduplicate agreeing canonical observations while retaining their provenance. Other observations are excluded with explicit ownership reasons. A Phresh test observation or originally primary-owned case is never a development owner.

Half of the newly eligible source is reserved to give its relatively scarce legitimate query formats useful representation on both sides. The fraction and hash rule are fixed before implementation or scoring. This is a new group-held-out cohort from a source also used for training, not an independent-source or chronological test. Phresh primary provides a separate historical source track, with shared-feed limitations.

Keep a 200,000-row pooled development ceiling. Include all eligible Mendeley development components first, counting every eligible row in each entire component. If that mandatory pool exceeds the ceiling, stop with `mandatory_development_components_exceed_cap`; do not truncate it or change the cap automatically. Fill remaining capacity with Phresh-only development components using the existing sorted, seed-42 whole-component selection rule. Record skipped components, source/class/format distributions and actual size. This predeclared source priority prevents the random size cap from accidentally discarding the measured supplemental coverage; it does not ensure that source annotations represent everyday browsing.

Allocate the selected components to train/validation/calibration using the existing deterministic class-balancing algorithm and target 80/10/10, seed 42. Publish achieved fractions. Allocation may use labels for balance but never model scores. Do not try other seeds, alter the half-reservation rule or borrow final cases to pass support gates.

## Gates and immutable fitting inputs

Training requires at least 1,000 rows and 100 domain groups per class. Validation, calibration, primary and supplemental each require 100 rows and 30 domain groups per class. Report connected-component support separately. Both final tracks, pooled development and the actual training partition each require at least 100 legitimate non-root-path URLs, 100 legitimate non-www URLs and 30 legitimate query URLs. Overlapping strata are allowed. These are minimum coverage checks, not claims of representativeness, calibration or accuracy.

Require both sources to contribute at least 100 rows and 30 domain groups per class to the pooled development cohort. Per-source partition and format counts remain visible even where a subgroup is too small for meaningful uncertainty estimates. All required gates must pass before a pilot or learner runs. A failed gate produces a negative research-status/card with null metrics and no fitted artifact. Preserve the frozen failed protocol; new data or changed decisions require a separately versioned experiment.

Before every pilot, fit and final evaluation, verify the physical audit/protocol files, exact partition keys, row content and labels, assignment digests, components, owners, source bindings, parser/PSL, parent anchors and config. Reject missing private root handles, shadow partitions, in-memory mutation and changed frozen files before any learner or artifact deserialization boundary. No partial or manually assembled unverified split bundle reaches fitting.

Research evaluation can load the diagnostic only after its own checks. Hashes detect corruption, not trust in downloaded pickle files; no artifact-upload endpoint is added. ## Failure behavior and delivery checks

The research CLI exposes explicit stages: `bind-v2`, `acquire-mendeley`, `audit`, `freeze`, `pilot`, `train`, `evaluate` and `predict`. The v3 root is required except for explicit artifact prediction; `bind-v2` takes the read-only v2 input root. Later stages consume the verified binding and immutable v3 outputs. Each stage exits nonzero with a preserved, sanitized diagnostic on failure, never claiming that a partial source or missing track passed. Prediction needs no data root. No silent acquire/train sequence runs on server startup.

Regression-first checks must cover official-host redirects and budgets, changed file identity, exact full-file hashes, orphan/interrupted recovery, UTF-8/CSV/header errors, missing/unknown labels, cross-source contradictions, unchanged v2 anchors even after conflicts, component ownership, primary-subset preservation, fixed half-reservation, mandatory-cap failure, deterministic allocation, missing class/source/format support, mutable splits and physical sidecars, final-access fitting refusal, metadata-before-deserialization, v1/v2 compatibility and unchanged stdlib-only server startup. Synthetic software fixtures are identified and never reported as research cases. Existing web-client checks must still pass.

Real execution, if approved, must verify source bytes and measure the joint audit/cohorts before attempting the resource pilot. Run the full fit and frozen final evaluation only when those gates pass. Record a trained research candidate and measured limitations, or a truthful incomplete outcome with no model/accuracy claim. Protect the original v1 artifact/environment, v2 source/audit/protocol, case database and empty paired-message intake. Raw source/model data stay private when code, docs and aggregate results are pushed to the existing private repository.

Learned application warnings remain disabled. External or contemporary real-use validation, browser/application release checks and a separate reviewed activation decision follow this research milestone. A historical URL benchmark does not answer the year-long paired message/link research question or establish live site safety.
