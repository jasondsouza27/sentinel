# Real message–link source audit

NC State and PhishNet were checked on 2026-10-04; the legitimate-message source search and candidate selection below were completed on 2026-10-05. This is a source-selection record, **not** a phishing-model evaluation. The raw files and candidate sheets stay in Git-ignored `data/` files and are not copied into the team intake automatically. Git ignore does not prevent cloud sync, so keep unreviewed messages and source metadata in an approved storage location outside synced folders. No submitted link was opened.

## Recommended positive-case source: NC State SMS phishing release

The authors of [*On SMS Phishing Tactics and Infrastructure*](https://robocall.science/publication/sp24/) studied SMS phishing collected from public gateways. Their [dataset release](https://github.com/wspr-ncsu/sms-phishing) supplies original messages and a separate campaign table; the repository includes an [MIT license](https://github.com/wspr-ncsu/sms-phishing/blob/main/LICENSE). Confirm the data-reuse terms before redistribution. The release describes the messages as identified using VirusTotal and APWG. Use the paper and release when citing the source, and keep that source label distinct from Sentinel's later two-reviewer label.

The locally downloaded `phishing_messages.csv` has SHA-256 `d125c394af792faeb2b71b3f7100cad3b4cece02aff78cb4ec1fb9e7db90f230` and 68,029 rows. Sentinel found exactly one HTTP(S) or `www.` link-shaped occurrence in 40,271 rows. These are **candidate pairs**, not 40,271 approved cases. The paper reports 67,991 phishing messages, while the current CSV has 68,029 rows; record this 38-row difference and audit exclusions before quoting a final sample count.

The companion `phishing_campaigns.csv` has SHA-256 `f23a56037ca3e4d5aceb34536c11c7fff37174f7618ff943e855820f550600a5` and 35,128 rows. Its `objectID` values do not overlap the message file's `objectID` values, so a direct campaign-ID join is unsupported. Do not guess campaign IDs from row order or matching wording. Sentinel can still prevent identical wording and destination domains from crossing its train/test split. Reviewers can assign `campaign_group` when they have independent evidence that different cases belong to one campaign.

The local importer selected [100 candidates](../data/curation/ncsu_candidates.csv) from this release using seed 42. It first removed messages without exactly one recognizable link occurrence and duplicate message–URL pairs, leaving 8,085 eligible pairs. It then selected distinct destination-domain groups and distinct URL-stripped wording. The [counts-only import audit](../data/curation/ncsu_candidates_audit.json) records the source and output hashes and exclusion counts. Reproduce the selection after placing the source CSV in `data/source_ncsu_phishing_messages.csv`:

```powershell
.\import-ncsu-candidates.cmd data\source_ncsu_phishing_messages.csv data\curation\ncsu_candidates.csv --audit-out data\curation\ncsu_candidates_audit.json --limit 100 --seed 42
```

The command refuses to overwrite an existing candidate file. Open candidate CSVs as UTF-8 text or import every spreadsheet column as Text; untrusted message content may otherwise be interpreted as a formula. `collection_basis`, `collected_on`, and `redaction_reviewed` are intentionally blank. Before copying a candidate into `data/curation/intake.csv`, a team member must inspect the original message for personal details and secrets, verify the URL was in that message, retain its opaque source reference, confirm the source's reuse terms, and fill those fields. The raw source contains a destination-number field; the importer never copies it. The two reviewers must still decide whether the individual case fits Sentinel's phishing label. This source provides **phishing candidates only**; it cannot alone produce a valid binary test set or a message-plus-URL comparison.

## Rejected as a complete paired dataset: PhishNet curated SMS

The [PhishNet authors' repository](https://github.com/AbeerAlhuthali/PhishNet) supplies a three-class curated SMS file and says its custom dataset is for academic and research use with citation. The locally downloaded `PhishNet_Dataset2.csv` has SHA-256 `eed49445a7838a9f89dc00ab9a5d6843e64bc9c14a3e6203b8537186bf80f0be` and 2,997 rows: 997 smishing, 1,000 ham, and 1,000 spam. Sentinel's extractor found one link in 553 smishing rows, but **zero** links in the ham and spam rows. It is therefore unsuitable on its own for testing whether combined message and URL evidence improves detection. Calling all spam phishing would also change the authors' label meaning.

## Potential legitimate-message sources checked on 2026-10-05

The [UCI SMS Spam Collection](https://archive.ics.uci.edu/dataset/228/sms+spam+collection) provides original SMS text with spam/ham labels and publishes a CC BY 4.0 licence. Its current archive has SHA-256 `1587ea43e58e82b14ff1f5425c88e17f8496bfcdb67a583dbff9eefaf9963ce3`. Sentinel counted 5,574 records: 4,827 ham and 747 spam. Only two ham records contain an extractable link; they are duplicate message–link pairs, leaving **one distinct candidate**. A ham label concerns spam classification; it does not independently establish that an individual linked request is legitimate. UCI's spam records were not added to the phishing pool.

The [NUS group's English SMS release](https://github.com/WING-NUS/nus-sms-corpus) contains 55,835 messages in its 2015-03-09 XML archive. The downloaded archive has SHA-256 `bf73d77fce35c703dab21826cd2c1698205358c2c25b2d43da1f08671b825bdc`. The [authors' methodology](https://arxiv.org/html/1112.2468) describes volunteer collection, URL anonymization and unrestricted public use; the release requests a citation to Chen and Kan (2013). The repository does not provide a separate named licence file. Keep that description distinct from UCI's explicit CC BY licence and check the release terms before any redistribution.

This NUS release has **no phishing or legitimacy labels**. A volunteer contribution is provenance, not proof of a legitimate request. Sentinel found 24 messages with one recognizable link, and 23 messages containing an anonymized `<URL>` placeholder. It excluded placeholders, malformed links and duplicate pairs, leaving 21 distinct eligible pairs. Do not reconstruct anonymized destinations or attach a replacement URL. The XML also reuses 10,117 message ID values: its 55,835 records have only 45,718 distinct IDs. Each selected case therefore references its one-based XML message position as well as its original ID, within the hash-identified archive. An ID-only lookup would be ambiguous.

### Local review batch

The [candidate sheet](../data/curation/legitimate_sms_candidates.csv) contains **18 unreviewed potential legitimate SMS cases**: one from UCI and 17 from NUS. Selection used seed 42, considered UCI first, and retained at most one candidate per destination-domain group and URL-stripped wording across both sources. The [counts-only audit](../data/curation/legitimate_sms_candidates_audit.json) records exclusion counts, source/member hashes, selection rules and output hash. The candidate sheet's SHA-256 is `20c478680f93881c80acb1cffb99999a160513a5d89b08cfbe2f9f9604d02d37`.

Only the message text, its extracted link and an opaque source record reference were copied. NUS sender, recipient and demographic metadata were not copied. The sheet has the same columns as the intake, with `collected_on`, `collection_basis` and `redaction_reviewed` deliberately blank. It contains no Sentinel labels. Open it as UTF-8 text, or import every spreadsheet column as Text, then inspect personal details, source evidence and the actual message–link pairing before admitting a case. The existing 100 NC State candidates were not changed; `intake.csv` still has zero rows.

These 18 cases form a small collection starting point, not a balanced training or test dataset. The old corpus dates and differing collection sources could let a model distinguish datasets rather than deception. A larger, verified legitimate sample from a comparable channel and period remains necessary. Preserve unclear or unverifiable cases as `?` or exclude them; do not assign legitimate labels merely to balance the classes.
