## Delivered behaviour and research outcome

The application accepts ordered linear/reply conversations with an explicit
target, displays preceding-context coverage and cautious separate assessments,
and saves the exact signed snapshot the user reviewed. It supports reopening,
feedback, export and deletion. New clients require a 900-second process-local
receipt; expired/restarted receipts require a recheck. Legacy input-only saves
remain compatible and explicitly create a new assessment.

The research package implements verified CAD admission, protected author/duplicate
ownership, fixed development allocation, bounded sparse CPU candidates,
conditional pinned encoder tooling, supported calibration, checked artifacts,
one-time final access and a reproduction CLI. New raw data and models stay ignored.

The real CAD study is **unavailable**, as permitted by the approved plan's gates.
The fixed allocation has 175 positive training cases against a minimum of 200,
five validation components and eight calibration components against a minimum
of ten. No real replacement partitions, harm model, encoder package/model bodies,
neural environment, CUDA pilot, protected final score or learned live warning
were produced. The challenge is empty/pending. See the
[research card](../output/research/context-harm-v1/model-card.md) and
[aggregate status](../output/research/context-harm-v1/research-status.json).

## Decisions made during execution

1. Used the ignored local Git worktree after native managed creation could not
   validate the moved repository reference. Cost: manual preservation/cleanup.
2. Used scoped task tests and an integrated whole-project run. Cost: hidden
   coupling could first appear during integration.
3. Parallelized independent ownership after the user's explicit request. Cost:
   shared interfaces needed coordinating checks.
4. Excluded whole malformed ancestry threads while retaining original source
   records for protected ownership. Cost: reduced source coverage.
5. Preserved raw target/context for observations and applied masking at feature
   boundaries. Cost: each feature/token path must use the shared preparation;
   isolation tests verify this boundary.
6. Committed coupled encoder tasks together after both scoped suites passed.
   Cost: Task 7 has no independent Git checkpoint without Task 8.
7. Preserved the CPU pin-only lock and corrected reproduction to binary installs,
   exact inventory verification and `pip check`; only the encoder lock requires
   hashed offline wheels. Cost: CPU admission relies on the official registry and
   exact versions rather than a wheel-body lock.
